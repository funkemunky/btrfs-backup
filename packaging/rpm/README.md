# Fedora RPM Builds

Fedora 44 is the baseline. Run these commands from the checkout root on a
conventional Fedora 44 system. Build as your ordinary user; DNF installs build
dependencies with administrator privileges:

```bash
sudo dnf install python3 git rpm-build systemd-rpm-macros dnf5-plugins
python3 tools/build_fedora_rpm.py --srpm-only
sudo dnf builddep --assumeyes dist/fedora/btrfs-backup.spec
python3 tools/build_fedora_rpm.py
cd dist/fedora
sha256sum --check SHA256SUMS
```

The helper stages the current working tree, including uncommitted source edits,
using the release archive code. It renders the version from `VERSION` and runs
`rpmbuild -ba` in a temporary build root. `%check` runs the unprivileged CTest
suite; compiler architecture probes, privileged device tests, upstream CI workflow
contracts and generic/Arch package-generation tests are excluded.
The base build explicitly enables the system manager and disables KDE.

`dist/fedora/` receives the source tarball, rendered spec, SRPM, binary RPMs
(including debug packages when generated by Fedora), and `SHA256SUMS`.
`--dist-dir PATH` selects another output directory. Use a dedicated directory
for each build; generated files with matching names are replaced. The checksum
manifest covers only that invocation's artifacts. `SOURCE_DATE_EPOCH` defaults
to the last commit timestamp and may be set explicitly for archive repeatability.
Binary reproducibility requires the same Fedora toolchain and dependencies.

To produce the optional Plasma package, install the KDE build dependencies from
the [Fedora development guide](../../docs/development.md#fedora-44-development),
then run:

```bash
python3 tools/build_fedora_kde_rpm.py
```

To produce the GNOME 50 integration package, install its Fedora runtime and
build tools, then run:

```bash
sudo dnf install gjs glib2-devel gtk4 libadwaita python3-gobject nautilus-python
python3 tools/build_fedora_gnome_rpm.py
```

This writes `btrfs-backup-gnome-<version>-1.fc44.<arch>.rpm` into
`dist/fedora/`. The package requires the matching `btrfs-backup` package plus
GNOME Shell 50, GJS, Python GObject, GTK 4 and libadwaita. Nautilus Python is a
weak dependency for the Files previous versions action. Install the base and
GNOME RPM together so DNF can resolve the package dependency:

```bash
version=$(cat VERSION)
sudo dnf install \
  "dist/fedora/btrfs-backup-${version}-1.fc44.$(uname -m).rpm" \
  "dist/fedora/btrfs-backup-gnome-${version}-1.fc44.$(uname -m).rpm"
```

This creates `btrfs-backup-kde-<version>-1.fc44.<arch>.rpm`, requires the
matching `btrfs-backup` base package, and adds itself to the checksum manifest.
Install both packages together so DNF can resolve the package dependency:

```bash
version=$(cat VERSION)
sudo dnf install \
  "dist/fedora/btrfs-backup-${version}-1.fc44.$(uname -m).rpm" \
  "dist/fedora/btrfs-backup-kde-${version}-1.fc44.$(uname -m).rpm"
```

For a clean distribution build, rebuild the SRPM with Mock:

```bash
sudo dnf install mock
python3 tools/build_fedora_rpm.py --srpm-only
version=$(cat VERSION)
sudo mock -r fedora-44-x86_64 --rebuild \
  "dist/fedora/btrfs-backup-${version}-1.fc44.src.rpm" \
  --resultdir "$PWD/build/fedora-mock"
```

For an isolated build with Podman, create the artifact directory first:

```bash
mkdir -p dist/fedora-container
podman run --rm \
  -v "$PWD:/work:ro" -v "$PWD/dist/fedora-container:/artifacts:rw" \
  --workdir /work fedora:44 bash -c '
    dnf install -y python3 git rpm-build dnf5-plugins &&
    python3 tools/build_fedora_rpm.py --srpm-only --dist-dir /artifacts &&
    dnf builddep -y /artifacts/btrfs-backup.spec &&
    python3 tools/build_fedora_rpm.py --dist-dir /artifacts
  '
```

On SELinux hosts, run from a dedicated checkout and add `:z` to the mount
options if container access is denied. The repository remains read-only in
the container, and build/install staging happens in its temporary filesystem.

The `Fedora RPM` GitHub Actions workflow builds both packages on Fedora 44,
uploads `fedora-44-rpms`, then verifies checksums and installs them with DNF in a
fresh container. It checks installed file integrity, CLI, manager and restore
help, systemd/tmpfiles paths, the KDE KIO plugin, trusted-hook ownership and the
base package's independence from Qt/KDE. It does not start services or touch
backup devices. RPM runtime dependencies include `systemd-udev`, which supplies
`systemd-cryptsetup` on Fedora. Library dependencies are generated
automatically from ELF files.

The spec owns individual D-Bus files, completions, manuals and tmpfiles
declarations. Fedora's systemd file triggers handle manager reloads and tmpfiles
creation; no application migration or service restart scriptlet is added.
Booted-system and real backup/restore checks belong in disposable Fedora VMs.
The optional KDE integration can be developed from source using the
[Fedora development guide](../../docs/development.md#fedora-44-development).
